# Four-week CyberNova learning path

The goal is not to rush through tools. It is to understand a small concept, implement or explain it, test it, and record what you learned.

## Week 1 — Python and Git foundations

- Run every CyberNova command and describe its input and output.
- Read `src/cybernova/hashing.py` and learn why files are read in chunks.
- Practise `git status`, `git diff`, `git add`, `git commit`, and `git log`.
- Add two quiz questions and tests.
- Write a short weekly reflection in a GitHub Discussion or issue.

**Mini milestone:** explain a commit, a branch, and a hash in your own words.

## Week 2 — Security foundations

- Learn confidentiality, integrity, and availability (the CIA triad).
- Compare authentication and authorisation.
- Learn least privilege, defence in depth, and threat modelling.
- Use the integrity tool on a folder of harmless sample files.
- Draw a simple threat model for CyberNova in a Markdown document.

**Mini milestone:** explain what the integrity monitor can and cannot prove.

## Week 3 — Systems and networks

- Learn Linux navigation, users, groups, and file permissions.
- Learn IP addresses, ports, DNS, HTTP, HTTPS, and TLS at a conceptual level.
- Use legal practice environments such as OverTheWire Bandit or your own virtual machine.
- Add a quiz category for systems and networking.

**Mini milestone:** explain what happens after you type a safe website address into a browser.

## Week 4 — Open source workflow

- Open a clear issue for one roadmap item.
- Create a branch, implement the change, and add tests.
- Open a pull request that includes screenshots or terminal output.
- Ask a classmate to review it.
- Merge it only after the automated checks pass.
- Make one documentation contribution to a beginner-friendly public project.

**Mini milestone:** share a pull-request link that demonstrates how you respond to review feedback.

## Evidence for your portfolio

For each feature, keep a short note with:

1. the problem you tried to solve;
2. the security concept involved;
3. one design choice and its trade-off;
4. how you tested it;
5. what you would improve next.

This evidence is much more valuable than a crowded contribution graph. It helps you talk clearly in interviews and shows genuine growth.

## Safe practice rule

Use only your own machine, deliberately vulnerable training labs, capture-the-flag environments that explicitly allow testing, or systems for which you have written permission. Cybersecurity skill includes knowing where the boundary is.
